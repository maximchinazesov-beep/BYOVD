# Актуальный анализ уязвимости типа BYOVD в драйвере WinRing0x64.sys

В этом репозитории представлен подробный анализ и технический разбор уязвимости в легитимном драйвере уровня ядра **`WinRing0x64.sys`** (также распространяемом под именем `WinRing0.sys`), который широко используется в утилитах для мониторинга аппаратного обеспечения и управления RGB-подсветкой (например, OpenRGB). Данный драйвер активно заносится в «черные списки» (blacklist) в общедоступных базах данных LOLDrivers и Microsoft.

## 🔍 Технический анализ

Статический анализ, выполненный в среде IDA Pro, позволил восстановить исходную логику и структуру уязвимого участка кода драйвера.

### 1. Создание устройства (RealDriverEntry)
Драйвер регистрирует символическую ссылку `\DosDevices\WinRing0_1_0_1` и создает объект устройства с помощью функции `IoCreateDevice`. Суть уязвимости заключается в том, что при создании объекта устройства **не были заданы списки избирательного управления доступом (DACL)**.

Это позволяет абсолютно любому локальному пользователю (даже с правами Guest или уровнем целостности Low Integrity) получить дескриптор устройства, используя стандартный вызов:
```cpp
CreateFileA("\\\\.\\WinRing0_1_0_1", GENERIC_READ | GENERIC_WRITE, ...);
```

### 2. Обработчик IOCTL (MajorFunction)
Основная функция-диспетчер (`sub_110D8`) обрабатывает управляющие коды, предназначенные для взаимодействия с аппаратным обеспечением. Она принимает ряд низкоуровневых управляющих команд (IOCTL) без какой-либо проверки токенов доступа или верификации привилегий. Внутренние функции считывают входной буфер непосредственно из пакета запроса ввода-вывода (IRP). ### 3. Произвольное чтение/запись MSR и прямой доступ к портам ввода-вывода
Внутренние подпрограммы полностью лишены каких-либо проверок привилегий вызывающего пользователя. Драйвер слепо доверяет буферам, предоставленным пользователем, и выполняет в пространстве ядра следующие привилегированные последовательности:

1. **`VulnerableReadMSR` (`sub_11494`) [IOCTL 0x9C402084]** — принимает индекс целевого регистра (значение типа DWORD) из пользовательского режима и передает его непосредственно встроенной функции **`__readmsr`**, возвращая 64-битное значение аппаратного регистра обратно в пользовательский режим.
2. **`VulnerableWriteMSR` (`sub_114C8`) [IOCTL 0x9C402088]** — принимает индекс целевого MSR-регистра и 64-битное значение из входного буфера, безусловно выполняя привилегированную инструкцию **`__writemsr`**.
3. **Прямой доступ к портам ввода-вывода [IOCTL 0x9C4060CC - 0x9C40A0E0]** — направляет входные данные из пользовательского режима непосредственно в аппаратные ассемблерные инструкции прямого доступа (семейство **`__inbyte`** / **`__outbyte`**), минуя ограничения доступа, налагаемые операционной системой.

## 💥 Реальный ущерб и потенциал атаки

Поскольку код выполняется на уровне привилегий Ring 0, он полностью обходит механизмы самозащиты операционной системы и стороннего программного обеспечения:
* **Обход KASLR:** Злоумышленник может инициировать произвольное чтение MSR-регистра `IA32_LSTAR` (`0xC0000082`) для получения точного адреса указателя ядра на функцию `KiSystemCall64`, тем самым полностью нейтрализуя защиту **KASLR**.
* **Локальное повышение привилегий (LPE):** Используя уязвимость, позволяющую произвольно записывать данные в MSR-регистры, злоумышленник может перезаписать `IA32_LSTAR` для перехвата обработчика системных вызовов ОС, перенаправляя поток выполнения ядра на полезную нагрузку, контролируемую пользователем, с целью получения полных привилегий **`NT AUTHORITY\SYSTEM`**.
* **Манипуляции с оборудованием:** Прямой доступ к портам ввода-вывода позволяет недоверенным локальным приложениям напрямую взаимодействовать с контроллерами материнской платы, что потенциально может привести к физической нестабильности оборудования или мгновенному зависанию системы. ---
